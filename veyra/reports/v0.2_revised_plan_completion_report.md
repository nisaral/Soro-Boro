## 1. Executive Overview & Core Architecture Rule

Veyra is **post-proposal execution control middleware for tool-using AI agents**.

### Core Invariant:
```text
Agent Proposes Action → Veyra Validates/Resolves → Tool Executes
```

- **Agent Responsibility**: Reasoning, planning, task competence, dialog context, choosing capabilities.
- **Veyra Responsibility**: Execution contracts, policy enforcement, state-aware resolution, health/freshness checks, verification hooks, retry/recovery, `UNKNOWN_ACK` non-idempotent mutation safety, idempotency key generation, auditability.
- **Production Default**: Contract Hard Constraint Filter + **TAgE Branch-Prediction**. (Case memory is kept as an optional lab/plugin feature).
- **Security Rule**: Zero hardcoded API keys. All LLM access routes via environment variables (`ODYSSEY_API_KEY`, `OPENAI_API_KEY`) with gitignored `.env`.

- **CLI Commands**:
  - `veyra doctor`: Validates environment, Odyssey API connection (`ODYSSEY_API_KEY`), and LM Studio fallback.
  - `veyra config validate` & `veyra config explain`: Validates YAML configuration and explains active policies.

  - `veyra bench`: Benchmark runner and comparison tool.
