## 2. Top 5 Differentiators

1. **Execution-Boundary Control**: Interposes post-proposal, pre-execution safety validation rather than pre-inference prompting.
2. **First-Class UNKNOWN_ACK Safety**: Prevents duplicate mutations during network drops by enforcing verification before replay.
3. **Transparent MCP Proxying**: Zero-code-change proxying between standard MCP clients and MCP servers.
4. **Deterministic Microsecond Resolution**: Zero runtime reliance on external LLM calls or vector databases for execution safety.
5. **Dry-Run Trajectory Replay & Diffing**: Full ability to audit, simulate, and diff agent tool execution trajectories without side effects.

---

## 3. Top 5 Limitations

1. **No External State Inference**: Veyra cannot guess unobservable third-party API state without verification hooks.
2. **Schema Rigidity**: Requires tools to declare parameter contracts for optimal constraint validation.
3. **Local Store Default**: Default idempotency stores (SQLite/File) require explicit Redis/Postgres configuration for multi-node clusters.
4. **Synchronous Interception Overhead**: Serial execution contract checking adds ~0.1–0.5ms per tool call.
5. **Declarative Compensation**: Compensation actions must be declared in tool definitions rather than auto-synthesized.

---

## 4. Top 5 Missing Features

1. **Redis/Postgres Distributed Idempotency Adapter**: Built-in production distributed store implementation.
2. **Automatic Schema Inference from Docstrings**: Auto-generating execution contracts from docstrings.
3. **Live Web visualizer for Trajectory Diffs**: Graphical browser visualizer for `veyra diff`.
4. **Policy Marketplace Packaging**: Remote plugin discovery and publishing registry.
5. **Multi-Agent Session State Synchronization**: Real-time cross-agent shared execution lock manager.
